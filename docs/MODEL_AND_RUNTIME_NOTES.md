# Notas de modelos y runtime

## ASR integrado

- La aplicación fija `ai.moonshine:moonshine-voice:0.1.5` en `gradle/libs.versions.toml`.
- Usa Moonshine **Tiny Streaming** (`MOONSHINE_MODEL_ARCH_TINY_STREAMING`) para inglés (`en`), español (`es`) y mandarín (`zh`). No usa las variantes antiguas no streaming. Para el modelo mandarín se carga `max_tokens_per_second=13.0`; los otros idiomas usan las opciones predeterminadas.
- La interfaz descarga el modelo del idioma de origen antes de permitir la captura. `MoonshineDownloadWorker.buildRequest(...)` ejecuta la descarga con WorkManager 2.9.1 y un nombre único por idioma; el trabajo persiste si se cierra la pantalla o muere el proceso. La solicitud requiere red conectada y aplica reintentos exponenciales; la UI observa `WorkInfo` y su progreso, y vuelve a conectarse al trabajo pendiente al reabrirse. El worker de Moonshine usa `AssetDownloader` para guardar en `files/moonshine/tiny-streaming/{en,es,zh}`; el downloader conserva archivos `.part` y continúa con HTTP Range cuando el servidor lo permite. Antes de marcar el modelo listo, la app lee el catálogo STT público del artefacto fijado, verifica tamaño y checksum CRC32C codificado en Base64 por archivo, y elimina los archivos cuyo contenido no coincida para que se vuelvan a descargar. El modelo preparado se puede inferir sin red.
- Los modelos Tiny Streaming de los idiomas elegidos están publicados bajo MIT en la documentación de Moonshine. La atribución y los avisos del artefacto se deben conservar al distribuir la app: [licencia y modelos](https://moonshine-voice.readthedocs.io/en/stable/license/), [modelos disponibles](https://moonshine-voice.readthedocs.io/en/latest/models/available-models/) y [release 0.1.5](https://github.com/moonshine-ai/moonshine/releases/tag/v0.1.5).
- El código fija el artefacto Android, y usa los CRC32C del catálogo incluido en esa versión para detectar archivos incompletos o alterados accidentalmente. CRC32C no es una firma criptográfica y el proyecto aún no registra hashes criptográficos independientes ni una revisión inmutable del catálogo; conservar esa limitación antes de una distribución comercial.
- La app guarda WAV mono PCM privado y segmentos/revisiones de transcripción y traducción en Room. Antes de capturar, la UI exige que Moonshine para el idioma de origen y M2M100 estén preparados y verificados. M2M100 se carga como parte de la sesión, recibe los segmentos ASR (no abre otra fuente de audio), y sus resultados se guardan/publican como una revisión posterior del mismo ID. La exportación M4A/TXT/JSON y la diarización quedan para fases posteriores.

## Runtime nativo

La inspección del AAR `ai.moonshine:moonshine-voice:0.1.5` confirma que empaqueta `libmoonshine-jni.so`, `libmoonshine.so` y `libonnxruntime.so` para `arm64-v8a`, `armeabi-v7a` y `x86_64`. El SHA-256 del AAR inspeccionado es `ee2d95c21150683c743db8f3aef66281fd5408bcefc94be3ca1d2545ada1f571`; el `libonnxruntime.so` ARM64 exporta la cadena de versión `VERS_1.23.2`. No se empaqueta un segundo `libonnxruntime.so`.

La biblioteca `libonnxruntime.so` que Moonshine 0.1.5 incluye es un build mínimo de ORT que rechaza modelos en formato `.onnx`; el texto de error es `ONNX format model is not supported in this build`. En el primer intento real en el Samsung Galaxy A56 5G SM-A566E con Android 16, la aplicación cargó el puente M2M100 pero el inicio falló al crear la sesión de los grafos fijados con ese error. La aplicación usa ahora como fuente el AAR `com.microsoft.onnxruntime:onnxruntime-android:1.23.2`, extrae su biblioteca ARM64 a `build/generated/ort-runtime-jni` y la empaqueta como el único `libonnxruntime.so` del APK. `merge*NativeLibs` verifica en cada variante el SHA-256 del archivo generado y del fusionado contra `e40f09d07dc53726b8bfbf48a7907673b8f86718a057655a62790a39874a7302`; así ninguna variante puede volver a introducir silenciosamente el build mínimo.

El puente M2M100 abre la biblioteca compartida con `dlopen`, resuelve `OrtGetApiBase` y exige la versión `1.23.2` y la API correspondiente a los headers C fijados. Si falla esa comprobación, no crea las sesiones. El APK de depuración se compiló con el runtime completo fusionado y se comprobó que ya no contiene las cadenas de rechazo del build mínimo. La aplicación no se ha instalado ni relanzado en el Galaxy A56 después del cambio; el comportamiento en ese dispositivo sigue pendiente de comprobación coordinada.

SentencePiece se compila desde el commit `17d7580d6407802f85855d2cc9190634e2c95624` del proyecto oficial v0.2.0 (Apache-2.0). CMake usa protobuf/absl internos y desactiva targets no necesarios. Aplica de forma idempotente un parche al CMake upstream para retirar únicamente el flag opcional `-fmacro-prefix-map` con ruta sin comillas: Clang separaba la ruta de checkout de Windows, que contiene espacios, y fallaba al compilar. El código del modelo y del tokenizador no se modifica.

Se compila el target JNI `voztranslate_m2m100` y los APKs para `arm64-v8a`, con NDK `29.0.14206865` y CMake `3.31.6`. La configuración admite el target de compilación en un checkout cuya ruta tenga espacios. El intento físico anterior sí llegó a cargar el puente y a la inicialización de la sesión M2M100, donde el runtime mínimo rechazó `.onnx`. El runtime completo se integró después y `assembleDebug`/`assembleRelease` se comprobaron localmente; el APK corregido aún no se ha instalado ni ejecutado en el Galaxy, por lo que no se ha confirmado su `dlopen`, la inferencia nativa ni la compatibilidad combinada con Moonshine en ese dispositivo.

### Traducción M2M100: archivos fijados y estado

- Modelo derivado ONNX INT8: [`huggingworld/m2m100_418M`](https://huggingface.co/huggingworld/m2m100_418M), commit inmutable `48f06c0fec544323fcf1546e312a617d962d3653`, derivado de [`Xenova/m2m100_418M`](https://huggingface.co/Xenova/m2m100_418M) / [`facebook/m2m100_418M`](https://huggingface.co/facebook/m2m100_418M). La tarjeta del derivado declara licencia MIT. El manifiesto de la aplicación usa URL `resolve/{commit}/...` y fija el tamaño y SHA-256 de cada archivo.
- `onnx/encoder_model_quantized.onnx`: 287,856,370 bytes; SHA-256 `13a94e354a9140764eb81102d77d3ec6952d796e6f113c651eeb3c3443da0386`.
- `onnx/decoder_model_merged_quantized.onnx`: 344,128,178 bytes; SHA-256 `007654bcabb6cea6fd3bde34ce933137b431330b3755781145d7b6906270b45a`.
- `sentencepiece.bpe.model`: 2,423,393 bytes; SHA-256 `d8f7c76ed2a5e0822be39f0a4f95a55eb19c78f4593ce609e2edbc2aea4d380a`.
- `vocab.json`: 3,708,092 bytes; SHA-256 `b6e77e474aeea8f441363aca7614317c06381f3eacfe10fb9856d5081d1074cc`.
- La descarga total fijada es 638,116,033 bytes (sin contar archivos temporales/reserva del sistema). La configuración del derivado declara cuantización QInt8 por canal.
- SentencePiece es el tokenizador del modelo; se conserva su licencia Apache-2.0: [SentencePiece](https://github.com/google/sentencepiece). El tokenizer fijado contiene 128,000 piezas y la tabla base `vocab.json` tiene 128,004 entradas. Transformers 4.33.0 define 100 códigos en [`FAIRSEQ_LANGUAGE_CODES["m2m100"]`](https://github.com/huggingface/transformers/blob/v4.33.0/src/transformers/models/m2m_100/tokenization_m2m_100.py); `M2M100Tokenizer` calcula sus IDs como tamaño base más índice. Los IDs son `__en__=128022`, `__es__=128023` y `__zh__=128102`. `128110` pertenece al bloque extra de ocho embeddings del modelo y **no** es el ID de `zh`.
- Semántica implementada: encoder `[src_lang_id] + SentencePiece(texto) + EOS`; decoder iniciado con `EOS`, seguido del ID destino forzado como primer token (`forced_bos_token_id` de Transformers). El puente ejecuta decodificación greedy con límite de longitud. El decoder combinado expone logits y 48 tensores de caché (key/value para 12 capas) según el grafo exacto.
- Para una pieza de SentencePiece que no aparece en `vocab.json`, el encoder usa ID `3` (`<unk>`), igual que el fallback `encoder.get(piece, encoder["<unk>"])` de [`M2M100Tokenizer`](https://github.com/huggingface/transformers/blob/v4.44.0/src/transformers/models/m2m_100/tokenization_m2m_100.py). El chequeo host con SentencePiece 0.2.0 y Transformers 4.44.0 produjo piezas fuera de vocabulario para `🫠🚀`, `🧬` y `𐍈`; el tokenizer oficial asignó ID `3` a esas piezas y los IDs comparados coincidieron. Esto valida la regla de tokenización en host, no una llamada JNI desde Android. El JNI consulta el flag de cancelación antes de codificar, antes de iniciar el encoder y entre pasos de decoder. Cada `OrtApi::Run` es una llamada síncrona: una cancelación que ocurra durante una de esas llamadas se observa después de que `Run` retorna, no la interrumpe inmediatamente.
- En el grafo combinado fijado, la rama `use_cache_branch=true` devuelve tensores `present.*.encoder.*` de longitud cero, aunque el prefill (`false`) entrega cachés encoder válidas con longitud igual a la secuencia de entrada. El puente retiene esas 24 cachés de encoder del prefill y en cada paso actualiza solo las 24 cachés `decoder.*`. El smoke host comprobó que la longitud de la caché decoder crece paso a paso y que las formas de la caché encoder permanecen iguales a las del prefill. Alimentar de nuevo las formas encoder de longitud cero de la rama cache hace fallar el `Reshape` del grafo.

El código Kotlin incluye un manifiesto pinneado, un descargador WorkManager reanudable por HTTP Range, SHA-256 antes de promover cada `.part`, un recibo atómico de instalación y `M2m100TranslationEngine.load(...)`, que vuelve a calcular los SHA-256 completos antes de crear el port JNI y sus sesiones. La UI presenta progreso/tamaño/error y requiere que ambos modelos estén listos. **READY de descarga** significa que los cuatro archivos están instalados e íntegros en esa comprobación; la sesión además carga el motor y su construcción de sesiones nativas debe tener éxito antes de abrir AudioRecord. La consulta ligera de preparación valida el recibo, las rutas privadas y los tamaños, sin releer 638 MB. Una corrupción posterior que conserve el mismo tamaño no se detecta por esa consulta, pero sí por la verificación completa que ejecuta el loader antes de cargar.

Al integrar la sesión, `SessionTranslationCoordinator` guarda y publica cada revisión ASR antes de programar traducción. Coalesce parciales obsoletos por ID y no inicia más de una inferencia parcial por intervalo de dos segundos. Los finales quedan durables en Room como filas `is_final` sin `translated_text`; una señal `Channel.CONFLATED` solo despierta a un worker serial que lee lotes limitados y ordenados por inicio/ID. Por tanto el consumidor ASR no espera al motor lento ni propaga su backpressure al canal PCM/WAV. Después de guardar cada final se consulta el `COUNT` durable de Room y se publica el backlog inmediatamente, incluso si el worker está ocupado traduciendo otro final. Al terminar el worker vuelve a reportar el conteo que obtiene con cada lote. Si una inferencia falla, la fila sigue pendiente y se muestra el error; el siguiente aviso de trabajo vuelve a consultar Room. Los resultados solo se guardan si coinciden todavía el ID, texto, revisión de origen y generación actual. Cada traducción aceptada obtiene una revisión monotónica nueva del mismo segmento, para que Room y `ActiveTranscriptStateStore` no rechacen una actualización posterior. La factory `RecordingTranslationEngineFactoryProvider` permite sustituir el motor para pruebas de servicio sin cargar JNI. No se ha medido el comportamiento en una sesión larga en dispositivo.

El smoke de referencia se ejecutó fuera de Android con Python, ONNX Runtime 1.23.2 CPU y los grafos, vocabulario y SentencePiece pinneados. La implementación oficial `M2M100Tokenizer` (Transformers 4.44.0) con los mismos dos archivos confirmó los IDs de idioma y las secuencias de entrada. Por ejemplo, “Good morning” se codifica como `[128022, 31092, 120665, 2]`; “Buenos días”, como `[128023, 57972, 14295, 2]`; para chino el tokenizer devuelve el ID de idioma `128102`.

Se ejecutaron doce traducciones greedy con frases equivalentes: “Good morning” / “Buenos días” / “早上好” y “How are you?” / “¿Cómo estás?” / “你好吗?”, cubriendo las seis direcciones para cada frase. Con `zh=128102` no hubo salidas vacías de mandarín ni repetición ilimitada de “Hello”. Por ejemplo, el smoke produjo “早安” para EN→ZH “Good morning” y “Good morning” para ZH→EN “早上好”. También hubo traducciones torpes o incorrectas, como “Buen mañana” y “¿Hejas bien?”. Esto verifica ejecución host del grafo con la secuencia de tokens y el uso de caché descritos, pero no acredita calidad ni es una comparación de salida con `model.generate` PyTorch del checkpoint original. Tampoco mide latencia o memoria en Android.

El puente JNI llegó a ejecutarse en el primer intento físico, pero la sesión M2M100 falló por el runtime mínimo descrito arriba. Después del cambio al runtime full, `assembleDebug` y `assembleRelease` compilaron; el APK nuevo sigue pendiente de instalar y probar en el Galaxy A56 5G SM-A566E con Android 16. La calidad semántica del smoke host tampoco está validada. Quedan pendientes la comparación cuantizada contra el modelo de referencia, evaluación humana bilingüe y medición en el teléfono objetivo, incluida RAM, latencia, batería y temperatura. No anunciar calidad o rendimiento verificados basándose en la descarga o el smoke host.

M2M100 se fija como artefactos ONNX INT8 y tokenizer descargables; el motor JNI/C++ greedy está conectado al flujo de la sesión y a la UI, pero no se ha ejecutado dentro de Android ni validado semánticamente. El tamaño de descarga está registrado; uso de memoria, latencia y calidad de la cuantización no se han medido en un teléfono.
